# Adaptive Routing Test Plan

## Scope

This plan verifies the adaptive health routing upgrade for grouped routing:

- Healthy / Degraded / Cooldown health states.
- Slow-success latency tracking.
- Soft-fail versus hard-fail cooldown behavior.
- Exponential cooldown backoff and half-open recovery.
- `fallback_only` route groups as current-request last-resort fallback targets.
- Provider `pricing_overrides` and cost ordering inside the same group / health bucket.
- Active probe as liveness-only detection, not routing health scoring.
- UI preservation of advanced health policy fields.

## Black-Box Simulation

Run the local relay lab:

```bash
MOCK_PORT=19111 BIFROST_PORT=18081 tests/manual/grouped-routing-lab/run_lab.sh
```

Expected:

- The mock relay uses local endpoints with the same provider/model shape as the online grouped route.
- Low-cost fast target is selected first while healthy.
- After repeated slow successes, that target becomes degraded and later healthy regular groups are preferred.
- When regular targets fail in the same request, the `fallback_only` target is appended and retried according to its `retry_limit`.
- Different provider pricing overrides change ordering only inside the same group and health bucket.

## Manual Behavior Checks

1. Fast success:
   - Send a grouped routing request through a healthy low-cost target.
   - Expected: target remains `healthy`; low-cost group remains primary.

2. Slow success:
   - Simulate at least 6 slow successes in a 10-sample window.
   - Expected: target becomes `degraded`; later healthy regular groups are selected before it.

3. Soft fail:
   - Simulate 429, timeout, quota, or saturated errors.
   - Expected: target enters cooldown using `cooldown_seconds * soft_cooldown_multiplier`, capped by `cooldown_max_seconds`.

4. Hard fail:
   - Simulate an unknown 5xx provider error.
   - Expected: target enters cooldown using base cooldown and backoff.

5. Half-open:
   - Let cooldown expire with `half_open_probe=true`.
   - Expected: exactly one half-open attempt is allowed; concurrent attempts stay cooldown.

6. Fallback-only:
   - Mark a high-quality group as `fallback_only=true`.
   - Expected: it is not selected as primary while any regular healthy/degraded target exists; it is appended to the same request fallback chain, so it is tried after regular targets fail. It becomes primary only when all regular groups are unavailable.
   - With one fallback-only target and `retry_limit=2`, expected: the fallback chain repeats that target three times, so two fallback failures can still be followed by a third successful fallback attempt.

7. Active probe:
   - Leave global probe mode passive.
   - Expected: no background probe traffic is generated by default.
   - If manually switching to hybrid and enabling one non-fallback target, expected: probe success/failure updates last probe fields only. It must not clear cooldown, trigger cooldown, or change routing health.

8. Pricing overrides:
   - Add two same-group healthy targets with different provider pricing overrides.
   - Expected: cheaper effective `input_cost_per_token + output_cost_per_token` is selected first within that group.
   - Make the cheap target degraded and the next group healthy.
   - Expected: health still wins; the later healthy group is selected before the cheap degraded target.

## Rollback Checks

To emulate old behavior for a rule, set:

```json
{
  "slow_ratio_threshold": 999,
  "slow_recovery_seconds": 0,
  "cooldown_backoff_factor": 1,
  "half_open_probe": false,
  "request_deadline_ms": 0
}
```

Expected:

- Slow successes still appear in snapshots but do not degrade routing by ratio or recency.
- Cooldown does not use exponential backoff.
- Cooldown expiry returns directly to normal routing without half-open single-flight.
